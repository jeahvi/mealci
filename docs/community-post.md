## V1 · 主贴（V2EX / 开发者社区）

**标题**：WorkBuddy × 麦当劳程序员节参赛作品：MealCI，给你的汉堡跑一次 CI（求 Star Orz..

**正文**：

**一、活动**

WorkBuddy 联合麦当劳搞了 1024 程序员节创意开发大赛：基于麦当劳官方 MCP 做一个 Skill。翻了翻已经出现的作品，热量计算、优惠券凑单、随机点餐……都是把 MCP 当查询接口单点调用。我想换个思路：**能不能不输出答案，输出一次代码评审？**

**二、MealCI 是什么**

一句话：你说"想吃点啥"，它把你这一单当成一次 git push，先跑完四道流水线再让你合入：

- **lint（营养检查）**：对照营养表逐项打标。超线不拦截，给 diff——"可乐换零度，-147 kcal，像删掉一行冗余代码"，回复 apply 一键回写购物车；
- **test（钱包测试）**：拉门店可用券做组合测试，输出 "N tests passed，省 ¥X"；券为空时输出 `CI 环境变量缺失：$COUPON 为空，本单按原价构建`；
- **build（取餐构建）**：查附近门店，"预计 12 分钟取餐——够你 review 完手头这个 PR 再走"；
- **review（习惯评审）**：拉历史订单说人话。我实测时它算出来一句："距上次 commit 已 265 天。本次为深圳分部首个 commit，祝构建顺利。"

四道全过输出一张 MR 卡：✅ Ready to merge / ⚠️ Changes requested。回复 merge 才创建订单，支付永远停在用户自己手里；回复 close 输出 rollback complete，不留任何订单。

**三、真实运行记录（全部来自 MCP 真实数据）**

```
 Merge Request !1024   麦门主分支 ← feat/order
 门店: 麦当劳深圳同方信息港餐厅 (403m, 营业至 23:00)
 lint:   ⚠ W401 sugary-drink: 可乐(中) 147 kcal
         → diff: 可乐 → 无糖可口可乐(中)  [-147 kcal]
 test:   ⚠ $COUPON 为空 — 该门店当前无可用券，按原价构建
 build:  ⏳ 到店自提 403m；今日可预约 夜市 17:14–21:45
 review: 💬 距上次 commit 已 265 天。深圳分部首个 commit。
 应付金额: ¥35.0（报价接口实价）
 状态: ✅ Ready to merge
```

彩蛋：23 点后 lint 切 strict 模式——"警告：此单属于 hotfix，建议回滚（睡吧）"；连续 5 单同款报"检测到循环依赖，注入一份蔬菜沙拉作为 break 语句"；合入成功输出 mock commit：`feat(order): 巨无霸×1 + 零度可乐×1, all checks passed 🍔`。

**四、技术上踩的坑（对后来者有用）**

- 麦当劳 MCP 是 Streamable HTTP + Bearer Token，`tools/list` 实际返回 **35 个工具**，比官方文档列的 24 个多——比如文档说没有订单查询，实际有 `order-list` / `query-order`，习惯评审阶段靠这个才成立；
- 营养接口返回的是 toon 紧凑格式不是 JSON，得自己按表头切列；
- 金额单位是"分"，展示前记得 /100，不然会把 35 块钱的汉堡报成 3500；
- 限流 600 次/分钟，穷举券组合时控制并发。
